# 静态资源与图标规范（团队）

本文档约定 **本地图标、符号图、小尺寸 PNG/SVG** 的导出、命名与接入方式，与 [前端开发总文档](./frontend-development.md) 中「静态资源」章节配套执行。提交 PR 时若涉及新增或替换图标，应自检本文 **第 4 节验收清单**。

## 1. 目的与适用范围

- **目的**：避免图标在真机或设计稿上「看不见」「整块发白/发黑」「与背景糊成一团」等问题，统一设计与前端交付标准。
- **适用范围**：随仓库提交的 `src/static/**` 下小图标、tabBar 图标、页面内 `<image>` 引用的本地位图；不含 CDN 大图与后端返回 URL。

## 2. 存放路径与命名

- **路径**：业务相关图标放在 `src/static/<业务域>/`，例如一键成片相关使用 `src/static/create/`，命名与现有文件风格一致。
- **命名**：语义化英文 + 类型后缀，小写短横线，例如 `create-icon-view-film.png`、`create-icon-arrow-down.png`。
- **格式**：优先 **PNG（支持透明通道）**；简单单色图形可评估 **SVG**（需确认目标端与构建链路支持情况）。
- **体积**：控制单文件体积，避免未压缩大图进入仓库；必要时走压缩工具或设计侧导出预设。

## 3. 图标导出规范（设计交付 / 切图必读）

### 3.1 优先使用透明底

- **推荐**：**透明背景** + 单一主色或双色线稿（与 UI 主色一致，如品牌橙 `#FF9432` 或纯白 `#FFFFFF` 二选一由场景决定）。
- **好处**：同一资源可同时用于浅色底、深色底、渐变按钮，无需为每种背景重复导出。

### 3.2 禁止或慎用「整底实色 + 反色图形」

- **问题典型**：**整块不透明黑底 + 白色图形**，或整块白底 + 浅色线稿。
- **在浅色容器上**：白图与白底容器叠加，缩略后图形轮廓与背景融为一体，表现为 **「只剩一块白 / 图标没了」**。
- **在浅色按钮上**：若仅去掉深色容器而不改素材，黑底会以 **深色方块** 形式盖在按钮上，视觉突兀。
- **团队约定**：除 tabBar、启动图等 **明确需要非透明画布** 的场景外，**禁止**将「整屏黑/白底」的导出图当作图标直接入库；应改为透明底或按 3.3 与前端对齐处理方案。

### 3.3 若历史资源仅有「黑底白标」位图

以下方案按 **推荐顺序** 选择其一（需与前端在 PR 说明中写清）：

1. **设计侧重导（首选）**：导出为 **透明底 PNG**，与 3.1 一致。
2. **前端临时兼容**：在 **确认目标端支持** 的前提下，可对图层使用 `mix-blend-mode: screen` 等叠色方式，使黑色与下层暖色底自然融合；**微信小程序部分基础库 / WebView 对混合模式支持不一致**，合并前必须在 **微信开发者工具 + 真机** 验证。
3. **前端显式衬底**：为图标单独使用与图形对比度足够的 **实色圆角底**（如深灰），使白标可见；此时图标区域与按钮底色 **刻意分层**，需与设计稿一致后再用。

**禁止**：在未改素材、未做兼容的前提下，将「黑底白标」直接放在 **白色或近白色** 的图标容器内并期望「看起来正常」。

## 4. 接入与代码侧注意点

- **路径**：与项目现有写法保持一致（如 `/src/static/create/xxx.png` 或经构建解析的 `@/static/...`，以当前页实际约定为准）。
- **`mode`**：小图标常用 `aspectFit`，避免 `aspectFill` 裁切丢关键笔画。
- **混合模式**：若使用 `mix-blend-mode`，须在 PR 描述中注明，并在 **小程序真机** 回归相关页面。
- **无障碍**：装饰性图标配合 `aria-hidden` 或等价处理，避免与邻近文案重复朗读（按页面已有写法对齐）。

## 5. 提交前验收清单（图标类改动）

- [ ] 资源为 **透明底** 或已在 PR 中说明采用的兼容方案（混合模式 / 衬底色）及验证端。
- [ ] 在 **设计稿对应背景**（白底 / 灰底 / 渐变按钮等）上预览无「消失」「糊边」「黑方块突兀」。
- [ ] **微信小程序** 目标页已真机或开发者工具预览通过。
- [ ] 命名、目录符合 **第 2 节**，未引入无关超大文件。

## 6. 文档维护

- 本规范随项目实践迭代；若与 `frontend-development.md` 中静态资源条目冲突，**以本文图标专项约定为准**，并同步更新总文档中的引用说明。
